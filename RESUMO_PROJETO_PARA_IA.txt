RESUMO GERAL DO PROJETO - BITCOIN DASHBOARD
===========================================

Objetivo do projeto
-------------------
Este projeto e um dashboard em Python para acompanhar o preco do Bitcoin em USD
e BRL. Ele busca dados da CoinGecko, converte USD para BRL usando a AwesomeAPI,
salva os dados tratados em um banco SQLite local e abre graficos interativos com
Plotly pelo menu de terminal.

O projeto atual funciona como uma aplicacao de linha de comando. Ao executar
`main.py`, ele atualiza o banco `database/bitcoin.db` e depois mostra um menu
para o usuario escolher qual visualizacao deseja abrir.


Estrutura atual dos arquivos
----------------------------
- `main.py`
  Arquivo principal. Executa o pipeline ETL, mostra o menu no terminal e chama
  as funcoes de visualizacao.

- `etl/extract.py`
  Responsavel pela extracao de dados externos via APIs.

- `etl/transform.py`
  Responsavel pela limpeza, transformacao, conversao USD/BRL, calculo de
  log-retornos, volatilidade e montagem das tabelas finais.

- `etl/load.py`
  Responsavel por salvar as tabelas transformadas no SQLite.

- `analysis/charts.py`
  Responsavel pelos dashboards interativos em Plotly.

- `analysis/metrics.py`
  Contem um grafico estatico antigo em Matplotlib. Hoje parece ser uma opcao
  auxiliar/legada, nao chamada pelo menu principal.

- `database/bitcoin.db`
  Banco SQLite local onde as tabelas tratadas sao gravadas.

- `requirements.txt`
  Dependencias do projeto.

- `README.md`
  Documentacao curta explicando o objetivo, execucao e opcoes disponiveis.

Como executar
-------------
Com o ambiente virtual configurado:

    .venv/bin/python main.py

O fluxo esperado e:
1. Atualizar dados via APIs.
2. Transformar os dados.
3. Salvar tabelas no SQLite.
4. Exibir menu de opcoes.
5. Abrir o grafico/consulta escolhida.


Fluxo principal em `main.py`
----------------------------
Funcoes existentes:

1. `run_pipeline()`
   - Busca historico de 365 dias do Bitcoin na CoinGecko.
   - Busca dados intraday das ultimas 24 horas.
   - Valida se as duas requisicoes deram certo.
   - Chama `tf.clean_data(raw_json, dados_intraday)`.
   - Salva as tabelas com `ld.save_all_tables_to_sqlite(tabelas)`.
   - Retorna o dicionario de tabelas tratadas.

2. `show_actual_price()`
   - Busca o preco atual do Bitcoin em USD via CoinGecko.
   - Converte o valor para BRL com `tf.usd_to_brl`.
   - Mostra os dois valores no terminal.

3. `open_dashboard()`
   - Mostra submenu com periodos:
     - 1 semana: `btc_1semana`
     - 1 mes: `btc_1mes`
     - 1 ano: `btc_1ano`
   - Chama `ch.plot_interactive_trend(tabela)`.
   - Abre o grafico com `fig.show()`.

4. `open_intraday()`
   - Abre o dashboard intraday usando a tabela `btc_intraday`.
   - Usa tambem `ch.plot_interactive_trend`.

5. `open_log_returns()`
   - Mostra submenu com periodos historicos:
     - 1 semana
     - 1 mes
     - 1 ano
   - Chama `ch.plot_log_returns(tabela)`.
   - Abre o grafico com `fig.show()`.

6. `main()`
   - Chama `run_pipeline()` sempre no inicio.
   - Mostra menu:
     - 1: Valor Atual
     - 2: Dashboards
     - 3: Intraday
     - 4: Log-retornos
   - Executa a opcao escolhida.


Extracao de dados em `etl/extract.py`
-------------------------------------
Constantes:
- `COINGECKO_BASE_URL = "https://api.coingecko.com/api/v3"`
- `REQUEST_TIMEOUT = 20`

Funcoes:

1. `_get_json(url, params=None)`
   - Faz GET com `requests`.
   - Usa timeout de 20 segundos.
   - Chama `raise_for_status()`.
   - Retorna JSON em caso de sucesso.
   - Retorna `None` e imprime erro em caso de falha.

2. `actual_value()`
   - Endpoint usado: `/simple/price`.
   - Parametros: `ids=bitcoin`, `vs_currencies=usd`.
   - Retorna o preco atual em USD.

3. `btc_intraday()`
   - Endpoint usado: `/coins/bitcoin/market_chart`.
   - Parametros: `vs_currency=usd`, `days=1`.
   - Retorna a serie de precos intraday das ultimas 24 horas.

4. `bit_history(days)`
   - Endpoint usado: `/coins/bitcoin/market_chart`.
   - Parametros: `vs_currency=usd`, `days=days`, `interval=daily`.
   - Retorna historico diario em USD.


Transformacao em `etl/transform.py`
-----------------------------------
Constante:
- `BR_TZ = "America/Sao_Paulo"`

Funcoes:

1. `usd_to_brl(usd)`
   - Busca cotacao USD/BRL atual na AwesomeAPI:
     `https://economia.awesomeapi.com.br/json/last/USD-BRL`
   - Usa o campo `USDBRL.bid`.
   - Multiplica o valor ou Serie em USD pela cotacao.
   - Retorna valor em BRL.

2. `retorno_log(df)`
   - Espera colunas `USD` e `R$`.
   - Calcula:
     - `log_return_USD`
     - `log_return_R$`
     - `volatility_21d_R$`
     - `volatility_21d_USD`
   - A volatilidade usa janela de 21 periodos e anualizacao com `sqrt(365)`.

3. `_prices_to_dataframe(prices)`
   - Recebe lista da CoinGecko no formato `[timestamp_ms, preco_usd]`.
   - Cria DataFrame com:
     - `data`
     - `USD`
     - `R$`
   - Converte timestamp de milissegundos para datetime.
   - Arredonda USD e BRL para 2 casas.

4. `intraday_data(dados_intraday)`
   - Valida se existem precos.
   - Converte timestamps UTC para `America/Sao_Paulo`.
   - Agrupa por hora usando media do preco em USD.
   - Calcula BRL usando `usd_to_brl`.
   - Retorna colunas:
     - `data`
     - `USD`
     - `R$`

5. `clean_data(dados_brutos, dados_intraday)`
   - Valida historico da CoinGecko.
   - Converte historico em DataFrame.
   - Calcula log-retornos e volatilidade.
   - Remove linhas com `NaN` geradas pelos calculos iniciais.
   - Retorna um dicionario com quatro tabelas:
     - `btc_1semana`: ultimos 7 pontos
     - `btc_1mes`: ultimos 30 pontos
     - `btc_1ano`: historico completo tratado
     - `btc_intraday`: dados intraday agrupados por hora


Carga em `etl/load.py`
----------------------
Funcao:

1. `save_all_tables_to_sqlite(dict_dataframes, db_path="database/bitcoin.db")`
   - Cria engine SQLAlchemy para SQLite.
   - Para cada item do dicionario `nome_tabela: dataframe`, salva no banco.
   - Usa `if_exists="replace"`, ou seja, substitui a tabela anterior.
   - Nao salva indice do pandas.
   - Imprime mensagem de sucesso para cada tabela.


Tabelas esperadas no SQLite
---------------------------
O pipeline grava estas tabelas:

1. `btc_1semana`
   - Serie historica curta com os ultimos 7 pontos tratados.

2. `btc_1mes`
   - Serie historica com os ultimos 30 pontos tratados.

3. `btc_1ano`
   - Historico completo tratado, vindo da chamada de 365 dias.

4. `btc_intraday`
   - Preco medio por hora nas ultimas 24 horas, no fuso de Sao Paulo.

Colunas esperadas nas tabelas historicas:
- `data`
- `USD`
- `R$`
- `log_return_USD`
- `log_return_R$`
- `volatility_21d_R$`
- `volatility_21d_USD`

Colunas esperadas na tabela intraday:
- `data`
- `USD`
- `R$`


Graficos em `analysis/charts.py`
--------------------------------
Este e o modulo mais completo da parte visual.

Constantes visuais:
- `DB_PATH = "database/bitcoin.db"`
- `BITCOIN_ORANGE = "#F7931A"`
- `POSITIVE_GREEN = "#16A34A"`
- `NEGATIVE_RED = "#DC2626"`
- `INK = "#172033"`
- `MUTED = "#667085"`
- `PANEL = "#FFFFFF"`
- `GRID = "#E4E7EC"`

Configuracao de moedas:
- `CURRENCY_CONFIG`
  - BRL usa coluna `R$`, simbolo `R$`, log-retorno `log_return_R$`.
  - USD usa coluna `USD`, simbolo `US$`, log-retorno `log_return_USD`.

Configuracao de periodos:
- `btc_1semana`
  - Titulo: Bitcoin - 1 Semana
  - Tick do eixo X: dia/mes
  - Sem media movel
  - Botoes de periodo: 7D e Tudo

- `btc_1mes`
  - Titulo: Bitcoin - 1 Mes
  - Media movel de 7 pontos
  - Botoes: 7D, 1M e Tudo

- `btc_1ano`
  - Titulo: Bitcoin - 1 Ano
  - Media movel de 21 pontos
  - Botoes: 1M, 3M, 6M, 1A e Tudo

- `btc_intraday`
  - Titulo: Bitcoin - Intraday
  - Mostra preco medio por hora
  - Sem range slider e sem media movel

Funcoes principais de graficos:

1. `get_data_from_db(table_name, db_path=DB_PATH)`
   - Le tabela SQLite com pandas.
   - Valida se nao esta vazia.
   - Valida colunas `data` e `R$`.
   - Converte `data` para datetime.
   - Ordena por data.

2. `create_title(table_name)`
   - Retorna titulo amigavel com base em `PERIOD_CONFIG`.

3. `choose_color(df, value_column="R$")`
   - Compara preco inicial e final.
   - Retorna verde se subiu, vermelho se caiu.

4. `_currency_settings(currency)`
   - Normaliza moeda escolhida.
   - Padrao: BRL.

5. `_format_currency(value, currency)`
   - Formata valores monetarios no estilo brasileiro.

6. `_format_percent(value)`
   - Formata percentual com virgula decimal.

7. `_period_stats(df, value_column)`
   - Calcula:
     - preco atual
     - maximo
     - minimo
     - variacao percentual do periodo

8. `_title_text(config, currency, stats)`
   - Monta titulo HTML do Plotly com subtitulo, moeda, preco atual,
     variacao, maximo e minimo.

9. `_range_selector(buttons)`
   - Monta botoes de periodo do eixo X no Plotly.

10. `_add_moving_average(...)`
   - Funcao auxiliar para adicionar media movel.
   - Observacao: existe no arquivo, mas o grafico principal implementa a media
     movel diretamente dentro de `plot_interactive_trend`, entao esta funcao
     parece nao estar sendo chamada atualmente.

11. `_price_annotations(df, stats, currency, line_color)`
   - Cria anotacao do preco atual.
   - Cria texto de fonte: CoinGecko e AwesomeAPI.
   - Informa que os botoes BRL/USD alternam a moeda.

12. `_current_price_shape(stats)`
   - Cria linha horizontal pontilhada marcando o preco atual.

13. `plot_interactive_trend(table_name="btc_1ano")`
   - Grafico principal de preco.
   - Le dados do SQLite.
   - Cria traces para BRL e USD.
   - BRL fica visivel por padrao.
   - USD fica oculto por padrao.
   - Adiciona botoes Plotly para alternar BRL/USD.
   - Atualiza titulo, eixo Y, anotacoes e linha de preco atual ao trocar moeda.
   - Adiciona media movel para os periodos configurados:
     - 7 pontos no mes
     - 21 pontos no ano
   - Usa area preenchida sob a linha.
   - Usa rangeslider para historicos, mas nao para intraday.
   - Retorna `go.Figure`.

14. `plot_log_returns(table_name="btc_1ano")`
   - Cria grafico de barras de log-retornos.
   - Funciona para BRL e USD.
   - BRL visivel por padrao.
   - Tem botoes para alternar BRL/USD.
   - Barras verdes para retornos positivos e vermelhas para negativos.
   - Usa rangeslider e range selector conforme periodo.
   - Retorna `go.Figure`.


Grafico Matplotlib em `analysis/metrics.py`

Pontos importantes para a proxima IA saber
------------------------------------------
- O app atual nao e web app Streamlit, apesar de `streamlit` estar nas
  dependencias. Ele roda via terminal e abre graficos Plotly no navegador.

- O pipeline roda sempre no inicio de `main()`. Isso significa que toda execucao
  tenta acessar as APIs externas e atualizar o SQLite.

- `usd_to_brl` chama a AwesomeAPI cada vez que converte. Como a transformacao
  chama essa funcao para historico e intraday, a mesma cotacao atual e aplicada
  aos precos historicos, nao a cotacao historica de cada data.

- As tabelas historicas removem as primeiras linhas com `NaN` apos calcular
  log-retorno e volatilidade. Como a volatilidade usa janela de 21 periodos,
  parte inicial da serie historica e descartada em `clean_data`.

- A tabela intraday nao tem colunas de log-retorno nem volatilidade. Por isso
  `plot_log_returns` deve ser usado apenas com tabelas historicas.

- `analysis/charts.py` possui a funcao `_add_moving_average`, mas ela parece
  redundante no estado atual, porque `plot_interactive_trend` adiciona a media
  movel diretamente.

- Nao foi encontrado repositorio Git ativo neste diretorio durante a inspecao:
  o comando `git status --short` retornou erro dizendo que nao e um repositorio
  Git. Portanto, este resumo considera apenas o estado atual dos arquivos.

- O ambiente local usado nesta analise tambem nao tinha o comando `sqlite3`
  instalado, entao a estrutura das tabelas foi inferida pelo codigo.

Resumo curto para contexto rapido
---------------------------------
Projeto Python de dashboard Bitcoin. Busca dados da CoinGecko, converte USD
para BRL pela AwesomeAPI, calcula log-retornos e volatilidade, salva tabelas em
SQLite e abre graficos Plotly via menu no terminal. Ja existem dashboards de
preco para 1 semana, 1 mes, 1 ano e intraday, com botoes BRL/USD, medias moveis
em alguns periodos, range selectors e grafico de log-retornos. O codigo esta
organizado em ETL + analysis + main. Ainda nao ha interface Streamlit ativa,
apesar da dependencia estar listada.
